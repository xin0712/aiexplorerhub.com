# 接真实工具：数据库 / API / 飞书

:::tip 先看结论
玩具工具和真实工具的差别只有一个字：**脏**。
真实数据有缺失、有格式混乱、有权限限制、有速率限制——这篇讲的都是「接了之后才发现」的事。
:::

## 这篇解决什么问题

前面几篇的工具是「造出来的」。这一篇接**真实系统**：数据库、第三方 API、企业协作平台。
难点不在调用本身，而在**数据质量、权限边界、失败处理**。

## 你会得到什么

- 三个真实接入的可运行示例
- 一套「接外部系统前的检查清单」
- 处理脏数据与限流的实用模式

## 本篇结构

### 一、接外部系统前，先问六个问题

1. 凭据怎么放（**绝不能写进代码**）
2. 有没有速率限制
3. 失败时返回什么（超时？错误码？空数据？）
4. 数据可能缺哪些字段
5. 这个操作可不可逆
6. 出错了谁负责（自动重试还是人工介入）

### 二、接数据库

- **只读优先**：先接查询，别急着给写权限
- 用只读账号
- 防止 Agent 生成危险 SQL（删表、全表扫描）
- 结果集太大怎么办（限行 + 分页）
- 跑一遍：让 Agent 查一个真实业务问题

### 三、接第三方 API

- 凭据管理（环境变量 / 密钥服务）
- 限流处理：429 怎么退避
- 超时与重试
- **计费意识**：有些 API 按次收费，Agent 可能一高兴调 100 次
- 跑一遍：接一个查询类 API

### 四、接飞书（企业协作平台）

- 应用创建与权限申请（最容易卡住的一步）
- 常见权限：消息、文档、多维表格
- 发消息 / 读表格两条最小路径
- 跑一遍：让 Agent 把结果发到飞书群

### 五、统一：给所有外部工具加一层「防护」

- 超时 + 重试 + 限流的统一封装
- 调用日志（出了问题能查）
- 成本统计（按次计费的 API 尤其需要）

### 六、常见坑

- **凭据硬编码**：提交进 git 就是泄露
- **权限给太大**：Agent 拿到了写权限，某天就把生产数据改了
- **忽略限流**：疯狂重试导致被封
- **脏数据没处理**：空值、格式错误让后续推理全错
- **可逆性误判**：以为能撤销的操作，其实不能
