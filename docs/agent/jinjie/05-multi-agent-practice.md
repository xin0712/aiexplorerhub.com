# Multi-Agent 实战：三种编排各跑一遍

:::tip 先看结论
多智能体不是「越多越好」。**先问一件事：这个任务真的需要多个 Agent 吗？**
很多时候拆成多个工具就够了——多 Agent 的价值在于**职责隔离**和**并行**。
:::

## 这篇解决什么问题

基础篇《Multi-Agent 多智能体系统》讲的是**有哪几种架构**。
这一篇讲的是**三种编排各写一个 demo**，并对比它们的实际开销与收益。

## 你会得到什么

- 顺序 / 并行 / 层级三种编排的可运行实现
- 一份「什么时候该用哪种」的判断依据
- 多 Agent 的成本感觉（token 通常是单 Agent 的几倍）

## 本篇结构

### 一、先回答：真的需要多 Agent 吗

- 需要：职责差异大、要并行、要隔离上下文
- 不需要：只是步骤多（那是单 Agent + 多工具）

> 坑：把「步骤多」误判成「需要多 Agent」，成本翻几倍、效果不一定好。

### 二、三种编排形态

| 形态 | 结构 | 适合 |
|---|---|---|
| 顺序 | A 做完交 B，B 做完交 C | 流水线任务（写 → 审 → 改） |
| 并行 | 多个 Agent 同时干，最后汇总 | 可独立拆分的子任务 |
| 层级 | 一个主管 Agent 分配、汇总 | 任务复杂且需要动态分工 |

### 三、顺序编排：跑一遍

- 场景：调研 → 写作 → 校对
- 每个 Agent 的输入输出契约
- 中间结果怎么传（传全文 vs 传摘要）
- 跑起来看结果

### 四、并行编排：跑一遍

- 场景：同时查 3 个数据源
- 并发控制与错误处理（一个失败怎么办）
- 结果合并策略（冲突了听谁的）
- 跑起来看耗时对比

### 五、层级编排：跑一遍

- 场景：主管 Agent 拆活分给下属
- 主管怎么知道该拆几步
- 下属汇报什么
- 跑起来看结果

### 六、三种形态对比

- 延迟 / 成本 / 可控性 / 调试难度
- 什么时候该退回单 Agent

### 七、常见坑

- **上下文重复传递**：每个 Agent 都带全量历史，token 爆炸
- **职责重叠**：两个 Agent 干同一件事，互相打架
- **无限委派**：Agent 之间互相甩锅，任务永远不结束
- **错误传播**：上游错了，下游照着错下去
