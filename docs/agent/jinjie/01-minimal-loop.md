# 手写一个最小 Agent 循环

:::tip 先看结论
一个 Agent 循环，最少只要四样东西：**一次模型调用、一张工具表、一个循环、一个退出条件**。
这篇我们不用任何框架，用几十行代码把它跑起来——看清框架替我们做了什么。
:::

## 这篇解决什么问题

基础篇的「从 0 开始构建一个 Agent」讲的是**架构**：任务边界、输入输出、Prompt、工具接口、Memory、Controller。
这一篇讲的是**代码**：把那份架构真的敲出来，并让它跑出结果。

读完你会得到：一个能自己调用工具、看结果、再决定下一步的最小 Agent，以及一份可以继续往上加东西的骨架。

## 你会得到什么

- 一个可运行的最小 Agent 循环（几十行）
- 一个能看懂任何 Agent 框架源码的心智模型
- 一份「框架到底帮我省了什么」的清单

## 本篇结构

### 一、先明确：一个循环最少需要什么

- 四个必需件：模型调用 / 工具表 / 循环控制 / 退出条件
- 哪三样可以暂时不要（记忆、多轮规划、错误恢复）

### 二、定一个真实任务

- 示例任务：让 Agent 查「北京今天天气」并回答
- 为什么选这个任务（一步工具调用，够简单又能看出循环）

### 三、v0：单轮调用

- 只发一次请求，让模型决定要不要调工具
- 看返回结构里的 `tool_calls`

### 四、v1：加上工具执行

- 定义工具表和实现
- 把工具结果作为 `tool` 消息回传给模型

### 五、v2：加上循环与退出条件

- 什么时候继续、什么时候停
- 退出条件的三种写法与各自的坑

### 六、跑起来

- 完整代码
- 运行输出
- 换个问题再跑一遍

### 七、常见坑

- **死循环**：模型反复调同一个工具
- **工具结果没回传**：忘记把结果作为消息追加
- **上下文爆掉**：循环轮数多了以后 token 失控
- **静默失败**：工具报错被吞掉，模型以为成功了
