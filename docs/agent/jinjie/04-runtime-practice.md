# Agent Runtime 实战：让它不崩、能续、可中断

:::tip 先看结论
Demo 和生产的差距，几乎全在 Runtime：**超时、重试、状态恢复、中断处理**。
这篇把 Runtime 从「概念」变成「能跑的一段代码」。
:::

## 这篇解决什么问题

基础篇《Agent Runtime》讲的是**Runtime 由哪些部分组成**。
这一篇讲的是**怎么把它实现出来**，并让 Agent 在真实网络和真实故障下活下来。

## 你会得到什么

- 一个带状态机的主循环
- 超时、重试、错误恢复的具体实现
- 「可中断、可恢复」的执行流

## 本篇结构

### 一、Runtime 到底在管什么

- 执行循环 / 状态管理 / 错误处理 / 生命周期
- 为什么「写个 while 循环」在 demo 够用、在生产不够

### 二、状态机：把 Agent 的执行变明确

- 有哪些状态（思考 / 调工具 / 观察 / 输出 / 等待 / 失败）
- 状态之间的迁移条件
- 为什么状态机比「一堆 if」更好维护

### 三、超时：每一层都要有

- 模型调用超时（不同模型差异很大）
- 工具执行超时（外部 API 可能永远不返回）
- 整体任务超时（防止跑一整天）
- 超时后怎么办：重试 / 跳过 / 上报

### 四、重试：什么时候该重试

- 可重试：网络抖动、限流（429）、服务端 5xx
- **不可重试**：参数错误（400）、权限不足（401/403）——重试只会浪费时间
- 退避策略：指数退避 + 抖动
- 幂等性：重试前先问「这个操作做两次会怎样」

### 五、错误恢复：三种失败三种处理

| 失败类型 | 处理方式 |
|---|---|
| 可恢复（工具临时失败） | 重试 / 换一条路径 |
| 不可恢复（凭据失效） | 停止 + 明确上报 |
| 部分成功（3 个工具成了 2 个） | 记录进度，从断点续 |

### 六、可中断与可续跑

- 用户中途取消：怎么优雅停下
- 进程崩了：状态存哪、怎么恢复
- 检查点（checkpoint）的实现思路

### 七、跑起来

- 完整代码
- 制造一次真实故障（断网 / 返回 500），看它的反应
- 中途 Ctrl+C，重启后看能否接上

### 八、常见坑

- **重试放大故障**：服务端已经过载，重试让它更糟（要有上限与退避）
- **超时设置过长**：一个卡住的工具拖垮整个任务
- **状态没持久化**：崩一次全白干
- **吞异常**：catch 了却什么都不做，问题被藏起来
