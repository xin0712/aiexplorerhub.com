# 框架深挖·动手篇：用 3 个框架搭同一个 Agent

:::tip 先看结论
评判框架的最好方法不是读文档，而是**用同一个任务把三个框架各搭一遍**。
感受它们的差异：写起来谁更顺手、调试谁更清楚、出错时谁能查。
:::

## 这篇解决什么问题

资料篇给了框架清单，高级篇会做源码级对比。
这一篇是**动手对比**：同一个任务，三种范式，各写一遍，然后比较。

## 你会得到什么

- 同一个 Agent 的三份实现（三个框架）
- 一份「手感对比」：上手成本、代码量、调试体验
- 一份属于你自己的选型依据

## 选哪三个框架

按**三种范式各挑一个**，覆盖主流路线，方便对比：

| 范式 | 候选 | 特点 |
|---|---|---|
| 图编排 / 状态机 | LangGraph | 生产级、状态与持久化强，适合复杂流程 |
| 角色多智能体 | CrewAI | 上手快、role 分工直观 |
| 轻量运行时 | OpenAI Agents SDK / Claude Agent SDK | 简单可控、贴近大模型原生 |

> 选型不是定论。你完全可以换掉其中一个，按自己的场景挑。

## 统一的任务

为了让对比公平，三个框架都实现**同一个任务**，建议选：

**「读一个本地数据文件 → 分析 → 输出结论」**

理由：够简单（不把时间花在业务逻辑上），又包含了工具调用与多步推理。

## 本篇结构

### 一、先说清楚怎么比

- **代码量**：实现同一件事写了多少行
- **上手成本**：从零到跑通花了多久
- **可读性**：隔一周回来看，能不能看懂
- **调试体验**：出错时能不能看到中间状态
- **生态与扩展**：要做更复杂的东西，顺不顺手

### 二、LangGraph 版

- 安装与最小示例
- 把任务表达成图（节点 / 边 / 状态）
- 跑起来
- 这一版的感受

### 三、CrewAI 版

- 安装与最小示例
- 把任务表达成角色分工
- 跑起来
- 这一版的感受

### 四、轻量 SDK 版

- 安装与最小示例
- 直接写循环 + 工具
- 跑起来
- 这一版的感受

### 五、三版并列对比

- 代码行数对比
- 同一次任务的 token 消耗对比
- 出错时的调试过程对比
- 结论：什么场景选哪个

### 六、常见坑

- **照着文档抄一遍就以为会了**——必须自己改一个需求
- **用同一个任务之外的场景下结论**——框架的优劣高度依赖场景
- **忽略版本差异**——照着旧版本文档写，跑不起来
- **只看上手速度**——上手快不代表生产好维护
