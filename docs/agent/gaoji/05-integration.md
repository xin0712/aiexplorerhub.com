# 与现有系统集成：Agent 怎么嵌进企业架构

:::tip 先看结论
企业里的 Agent 很少是「从零新建一个系统」，多半是**接到已有的流程里**。
最难的不是技术，是**边界**：哪些事交给它、哪些必须留给人。
:::

## 这篇解决什么问题

前面的内容都在讲「把 Agent 做好」。这篇讲**把它放进现有系统**：
对接已有数据、嵌入已有流程、与人和别的服务协作。

## 你会得到什么

- 一套集成方式的选择依据
- 权限与数据边界的处理方法
- 渐进式落地的路径

## 本篇结构

### 一、集成的四种形态

| 形态 | 说明 | 适合 |
|---|---|---|
| 嵌入工具 | 只给一个按钮 / 一个命令 | 单点提效，风险最低 |
| 旁挂助手 | 独立界面，人主动用 | 需要较长的交互过程 |
| 嵌入流程 | 流程中的一个环节由 Agent 执行 | 流程已标准化 |
| 自主执行 | Agent 自己判断并行动 | 高风险，需强护栏 |

> 建议：**从左边往右边走**，别一上来就做自主执行。

### 二、数据怎么接

- 直接连库（快，但权限风险大）
- 走已有 API（安全，但可能功能不全）
- 走数据同步（解耦，但有延迟）
- 选择依据：数据敏感度 + 实时性要求

### 三、权限怎么划

- 用服务账号，不用个人账号
- 权限按最小必要给
- 生产 / 测试环境隔离
- 敏感数据脱敏后再进上下文

### 四、人的位置

- 人在哪一步介入（建议：**决策点**而非每一步）
- 人怎么知道 Agent 做了什么（可读的执行记录）
- 出错了人怎么接管

### 五、渐进式落地路径

1. **影子模式**：Agent 跑但结果不用，只对比效果
2. **建议模式**：Agent 给建议，人决定
3. **半自动**：低风险自动、高风险确认
4. **自动执行**：仅限已充分验证的场景

### 六、和已有自动化（工作流 / RPA）怎么共存

- 边界：确定性的流程用工作流，需要判断的用 Agent
- 混合：工作流里嵌 Agent 节点
- 别用 Agent 重做已经稳定运行的工作流

### 七、常见坑

- **一步到位做自主执行**：没有验证期，出事就是大事
- **用个人账号接系统**：人一离职，Agent 就废了
- **没有回退路径**：Agent 出问题时，手工流程已经废了
- **忽略组织阻力**：技术上可行，但用的人不接受
